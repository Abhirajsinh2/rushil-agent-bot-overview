All runs use identical rules (0.75% stop-risk filter, 3R target, 1 concurrent position / 3 entries per day per direction per symbol, max 3 account-wide concurrent positions). Trades are approved purely on the strategy's own entry/exit logic — there is no cost-vs-edge filter gating whether a setup is "worth" the estimated transaction charges. Each dashboard still reports gross P&L, total charges, and net P&L per trade for visibility, but charges never block a trade from happening. Paper mode only — no real orders were placed, 1-share fixed sizing throughout.

The 4.7-year run exposed and fixed a real concurrency bug before these numbers can be trusted: two async callbacks (order-fill confirmation and position-close) had no ordering guarantee relative to each other, which could leave a "ghost" position permanently occupying one of only 3 account-wide trade slots when an entry and exit landed on the same candle. The first attempt at this backtest traded normally for 2.5 weeks, then silently stopped trading entirely for the remaining 4.6 years while reporting itself as blocked by its own position limits. Fixed in portfolio_state.py with a regression test that reproduces the exact failure. The numbers shown here are from the corrected re-run.

The 5m/10m full-history runs exposed a second bug, this one in Orchestrator.replay(): it built each tick's candle window as candles[:idx+1] — a full copy of everything seen so far — instead of the bounded 2-candle window IndicatorAgent actually reads. That's O(n²) memory, and on 5-min candles (~9x the tick count of 15-min) it crashed with MemoryError partway through; the 10-min run was heading the same way. Fixed by slicing candles[idx-1:idx+1] instead, verified against the full 52-test suite, then re-run. All three granularities above are now the full 2022-01-03 to 2026-09-18 range, not a short comparison window.

The time-based exit is rescaled per granularity to preserve Rushil's original ~120-minute hold intent rather than silently becoming a shorter or longer hold. All three converge to the same 36% win rate, which tracks — the entry/exit price rules are identical across granularities, only how often a setup is detected changes. 10-min comes out net positive across the full history; 5-min and 15-min are both net negative, with 5-min the worst of the three (most veto pressure, most whipsaw-prone signals).
